Recorded progress at this milestone:

This checkpoint records the sanitized operational decision supplied after the controlled Pilot validation. It distinguishes repository-backed design and test evidence from operator-confirmed observations. It contains no credentials, participant identities, private topology or application data.

## Validated state

The controlled Pilot validation reported:

- an isolated PostgreSQL instance with dedicated network and persistent storage and no host database port;
- all three reviewed migrations applied explicitly;
- a runtime database role operating with the expected least-privilege boundary;
- a real backup created and restored into a disposable target;
- application liveness and readiness checks passing;
- Multi-Family mode active and public registration disabled;
- the initial Owner and Family created through the temporary CLI-only bootstrap gate;
- the Owner password recovered through the temporary CLI-only reset gate;
- temporary administrative inputs removed before normal runtime;
- authenticated Family-context smoke checks passing.

These are sanitized operator-confirmed results. Publication should describe them as operationally verified only when the supporting evidence record can be shared safely. The repository independently documents the architecture, policies, disposable test harnesses and the reviewed administrative commands.

## Security boundaries

- Administrative bootstrap and password reset remain CLI-only, disabled by default and unavailable in Production or unknown environments.
- Public registration remains disabled.
- Migrations are explicit operator actions and never run at application startup.
- The application runtime role does not own the database or schema and is not granted DDL capability.
- No credential, connection string, participant identity or private infrastructure identifier belongs in Git or publication material.
- Tenant authority is derived server-side from authenticated membership and active Family context, not from a client-supplied `FamilyId`.

## Intentionally disabled or deferred

- public self-registration;
- automatic administrative bootstrap or password reset;
- notification delivery providers, including Telegram, unless separately approved;
- broad external access before the TLS and browser gate;
- automatic import or cutover from JSON;
- onboarding beyond the explicitly approved Pilot cohort.
